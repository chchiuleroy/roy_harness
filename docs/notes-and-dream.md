# 筆記與做夢（`remember`／`recall`／`/notes`／`/dream`）

模型可以把「看專案檔案猜不到」的經驗存成筆記，下次啟動時以**資料（不是指令）**載入；`/dream` 回頭看過去的對話，**只提案**，由你決定哪些套用。**預設開啟**，`HARNESS_NOTES=0` 關閉。

構想來自一支講 Claude 記憶四層架構與 dreaming 的影片（Gary Chen，2026-11-11）。影片說的 `auto dream` 觸發條件（超過 24 小時且至少 5 個對話）是講者轉述，**這裡沒有實作自動觸發，也沒有核對 Claude Code 原始碼**；這裡只有手動的 `/dream`。

## `MEMORY.md` 與 `AGENT.md` 不一樣

| | `AGENT.md` | `.harness_notes/MEMORY.md` |
|---|---|---|
| 誰寫 | **你** | **程式**，從各筆記的標頭產生（每條筆記一行：名稱與一句話） |
| 內容性質 | 給模型的規則，當指令信任 | 筆記的目錄，是資料，不是指令 |
| 模型能不能改 | 不能（受保護） | 不能直接改；模型存筆記時，程式才跟著更新它 |
| 手動編輯 | 照你寫的生效 | **下次啟動會被丟掉並重建**（不信任檔案裡的內容，以筆記本身為準） |
| 載入 | 啟動時整份放進系統提示 | 啟動時的目錄快照放進系統提示；具體筆記用 `recall` 讀 |

啟動時若 `MEMORY.md` 不存在就建立（所以預設開啟之後，每個專案資料夾第一次跑會多出 `.harness_notes/`，建議把它加進該專案的 `.gitignore`）。只有目前啟用的筆記會列在裡面；`pending` 的不會。筆記名稱不能叫 `memory`（Windows 不分大小寫，等於同一個檔）。

為什麼不讓模型自己維護目錄（像影片那樣）：模型寫的內容會直接進下一個 session 的系統提示，等於繞過「引文要來自你的話」的把關。目錄由程式從已通過把關的筆記產生，能得到同樣的檔，卻不開這條路。

## 設定

```
HARNESS_NOTES=0                 # 預設開；設 0 關閉，跟功能出現之前完全一樣（工具、系統提示都不變，也不建資料夾）
HARNESS_NOTES_DIR=.harness_notes   # 筆記資料夾，依目前工作目錄（和 AGENT.md 一樣是每個專案一份）
HARNESS_NOTES_AUTOLOAD=user     # user（預設）｜none（所有筆記都要你批准）
HARNESS_DREAM_MODEL=            # /dream 用的模型；沒設就用目前的模型
```

`.harness_notes/` 與 `.harness_dream/` 在 `.gitignore` 裡：筆記是個人的，不該進 repo。

## 信任規則

`AGENT.md` 與 skills 是**你**寫的，所以 harness 把它們當指令信任，並禁止模型改寫。筆記是**模型**寫的：它可能帶著工具輸出裡的注入文字。所以筆記**永遠不是指令**。

| 模型怎麼存的 | 結果 |
|---|---|
| `remember` 附的 `quote`（8–300 字）出現在**你打的字**裡 | `origin=user`，`active`：下次啟動進選單 |
| `quote` 只出現在**工具輸出**裡 | `origin=tool`，`pending`：不進提示，要你 `/notes promote` |
| `quote` 哪裡都找不到（含模型自己說過的話） | 拒絕，什麼都不寫 |

其他防線，都是程式判斷、不問模型：

- **選單是啟動快照**，由程式從筆記標頭產生（模型不維護索引）。中途存的筆記下次啟動才出現，因為每次請求都重建提示會讓伺服器的 prefix cache 失效。
- 讀回來時加**資料橫幅**，並跳脫結尾標記，內文不能偽造橫幅結束。
- 筆記內容若提到「只在工具輸出出現過、你沒講過」的主機，拒收（沿用來源追蹤）。
- 內文上限 2,000 字、描述 160 字、最多 100 條、選單 6,000 字。
- `write_file`／`edit_file` 與提到資料夾名的 shell 指令一律擋；子 agent 沒有這兩個工具；`safe` 模式每次存都問你。**例外（見〈已知限制〉）**：MCP 工具與你自己的 hook 不經過這些檢查。
- MCP 工具預設每次呼叫都問你；設成 `trust=always` 的 server，**當參數裡出現筆記或報告資料夾的名字時也照問**（只比對參數字串，同 shell 的做法）。
- 資料夾本身或筆記檔是連結（junction／symlink）就拒絕寫入或載入；暫存檔先清除再用 `O_EXCL` 建立，不跟隨預先放好的連結。
- 手寫、沒標來源的檔案視為 `tool/pending`：拿不準就不載入。
- 啟動時印出「新增／變更了哪幾條」與「等你批准的」。「變更」看的是**檔案修改時間**（不是檔案內的 `updated:` 行），時間基準是這次載入**開始**的時刻。這只是偵測，不是存取控制：能寫這個資料夾的工具也能寫標記檔、設定修改時間。

## 工具與指令

模型：`remember(name, description, body, quote)`、`recall(name)`。

你：

```
/notes                  列出全部（含 origin／status）
/notes show NAME        看原始檔（含 pending）
/notes promote NAME     批准 pending 的筆記（下次啟動生效）
/notes forget NAME      刪除
/dream [session.json …] 讀這個 session（與你指定的舊 session 檔），提案；只寫報告
/dream apply p1 p2      套用你點名的提案；只動筆記資料夾
```

## 做夢怎麼運作

1. 模型**沒有工具**，只收到帶編號的對話（`S1#12` = 第 1 個來源的第 12 則）、現有筆記與 `AGENT.md`，只回 JSON。
2. **程式逐一檢查每條引文**：引文必須逐字出現在它指的那則訊息（或筆記、`AGENT.md`）。找不到的提案丟掉並計數。
3. **誰說的由程式判斷**：在你的話裡 = `user`；在工具輸出 = `tool`；在模型自己的回覆 = `assistant`（不算你的話）；在 harness 的 reminder／壓縮摘要 = `reminder`（也不算你的話）。提案要變成自動載入的筆記，必須至少有一條 `user` 證據，**且全部證據都是你的話**（`user`、你自己的筆記、你的 `AGENT.md`）；只要混了一條工具輸出或模型自己的話，整條降成 `pending`。站在較弱筆記上的合併／編輯也不能「洗白」成 `user`。
4. 報告寫到 `.harness_dream/`（開啟筆記時，模型的檔案工具與 shell 碰不到它；同樣不含 MCP 與 hook）。**不會自動套用**。報告與指令摘要的「dropped」包含各種驗證失敗（格式錯、目標不存在、名稱衝突、找不到引文），原因列在報告最後。
5. `apply` 從記憶體裡剛才那次的提案執行（不讀檔，所以模型寫的檔案不可能被套用）。`add`／`edit`／`merge`／`delete` 只動筆記；`promote`（把教訓搬進 `AGENT.md` 或 skill）**只印出文字給你貼**。`merge` 的新名稱不能是不在合併來源裡的既有筆記；檔案無法一起改，所以先寫合併後的筆記、再逐一刪來源，刪除失敗會點名告訴你要自己 `/notes forget` 哪一條。

## 已知限制

- **殘留風險**：模型可以附一句真的使用者引文，卻把壞內容放進本文。引文證明「想法從哪來」，不證明本文忠實。補強是長度上限、主機檢查、資料橫幅與啟動時列出新增項目，但**擋不住說服力強的文字**，最後靠你看。
- 你貼進對話的文字算「你打的字」，程式無法分辨是你寫的還是你貼的。
- **任何能寫這個資料夾、又不經過 `remember` 的東西都能繞過全部檢查**：能寫檔的 MCP 工具、你自己寫的 hook。MCP 預設每次問你、名字出現在參數時連 `trust=always` 也問，但那是字串比對；hook 是你自己的程式，信任等級同 `AGENT.md`，harness 不替它把關。啟動時的「新增／變更」提示能發現被改過的檔案，但擋不住會一併改標記檔的工具。
- 兩個 harness 行程同時存同一條筆記，後寫的贏（與 session 檔的既有限制相同）。兩個行程存不同的筆記時，每次存之前都會重新掃磁碟再寫 `MEMORY.md`，所以不會互相漏列；但掃描與寫入之間仍有一個小窗口，漏掉的話下次啟動會從筆記重建。
- 連結防護是「先檢查資料夾不是連結、再寫入」，兩步之間沒有鎖：能同時操控父資料夾的人，理論上可以在中間把資料夾換成連結，讓暫存檔與改名落到資料夾外。純 Python 在 Windows 上沒有可用的「以目錄 handle 為基準」的寫入，這個窗口目前關不掉。（小o 第三輪審查指出，我核對屬實。）
- 預設開啟時，harness 會在目前工作目錄建立 `.harness_notes/`。superagent 的 ticket 與 bench 試驗固定關閉（`HARNESS_NOTES=0`，ticket 連 `.harness.env` 也改不了）；網頁 GUI 與一般命令列沿用預設開。其他直接呼叫 `harness_vllm.py` 的自動化要自己設 `HARNESS_NOTES=0`。
- 保護資料夾對 shell 只是字串比對，可被刻意混淆（與 `AGENT.md`、skills 相同）。
- `.harness_dream/` 的報告不會自動清理。
- 只在 Windows 11 測過。
