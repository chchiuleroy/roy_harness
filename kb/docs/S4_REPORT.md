## What S4 delivers (`src/kb/ask_*.py`, tier T3, plus `kb ask`, `kb answers`, `kb add --agent-visible --allow-external-model`)
`kb ask "<question>" --base-url ... --model ...` (measured, tests):
1. **Retrieval first, by kb's own code**: the same `Searcher` (committed content only; hidden and tombstoned things never); only collections that agents may see, and, when the endpoint is not on this machine, only collections that allow an external model. What is left out is reported by count and reason, never by id.
2. **Everything from outside is quoted data**: one message with a fixed header and footer, every line of documents and question prefixed `> `, names and labels cut to one printable ASCII line. A document cannot start a line with `/`, forge the footer or a section.
3. **The model has no tools**: a child process of the real harness (`harness_vllm.py --jsonl`), `safe` mode, a whitelist environment with every key pinned empty, a ticket folder whose hook vetoes every tool call (including unknown and MCP names), no MCP server configured, approvals answered `n`. The three lines of contact are the child process, the ticket's hook file and the environment; kb imports nothing of the harness and the harness knows nothing of kb.
4. **Answer and passages recorded by this layer** in an outbox file (`untrusted: true`), never overwritten: the answer text, each claim with its verdict, the passages exactly as sent (cleaned, cut; `chars_not_sent` says how much was left out), their origin (file, url, paste), a `kb open` hint, the commit id.
5. **A held answer waits for a person**: `kb answers release <id> --by <name>`; exit code 4 from `kb ask` when held.

## The four defence steps (C10), what each does and does not give
| Step | Does | Does not |
|---|---|---|
| 1 Quotes checked by code | Every claim must carry a quote that is a literal substring (after NFC and whitespace folding, at least 8 characters) of the passage it names, and of the text that was actually sent. Invented support is caught | A true quote used misleadingly; that a claim has anything to do with the answer's statement (checked by nobody) |
| 2 Origin labels and screening | Passages are labelled file / url / paste / other; text that looks like orders to a model (a short list of patterns, English and Chinese, plus many invisible characters) is left out of the prompt and listed for the person | Careful or paraphrased attacks, other languages, split or look-alike characters (小o's list of what gets past a short pattern list) |
| 3 The layer lists what the model was given | The person can check the answer against the very text it was built from, in one step, whatever the model wrote | Making the person look |
| 4 Held until released | Held when: a quote could not be checked, a passage came from a url, a paste or an unknown origin, a passage was flagged and left out, the reply is not in the agreed form, the answer has no claim at all, the turn timed out or the process ended early or the model call failed, the model asked for approval | A poisoned passage from a source the person approved themselves, used with a true quote in a reply that passes every check above: that answer is `ready`. **This is the accepted remaining risk**; step 3 is what keeps it visible |

Test of that last row (measured): a document that no pattern catches states a false password; the model repeats it with a true quote; the answer is `ready`, and the passage with the false sentence is in the record next to it.

## The deletion promise (H2) for what `kb ask` keeps
Found by me after the review, not by it: the answer record and the harness's session file hold the full text of the passages. Now: the ticket folder (prompt and session) is
removed as soon as the question has been answered, also when the run fails; an answer record whose passages include a hidden source, or a hidden unit of one, is removed
at the next commit together with its release marker (the same step that removes opened copies; a build cut off after the activation is finished by the next one, also when
nothing else changed). `kb inventory` lists both classes and the deletion canary test finds the text nowhere under `ask/` after hiding (measured: tests).

## What the second review of the erasure and the upgrade gate changed (2026-11-20, third 小o round, `docs/S4_REVIEW.md`)
The promise "hidden means the derived text is gone" had holes that only a second reader found; each was checked against the code, then fixed with a test and a mutant:
* **Proposals** that name a hidden source or unit (not the delete proposal itself) are blanked at the next commit in every state; an open one becomes stale first (that is what lets the existing trigger accept it, so no schema change was needed). They used to stay until their retention ended.
* **Backups:** once anything is hidden, every backup is removed at the next commit (the first version kept the ones made after the hide and before the erasure).
* **Retired commits with an unreadable manifest** are removed once something is hidden (they used to be kept as "doctor's business"); with nothing hidden they are still left alone.
* **Working folders of `kb ask`** (tickets) made before the newest hide, or older than an hour, are removed at the next commit; a crash used to leave one with the prompt text.
* **The bytes of the database file** (measured, not assumed): after a hide and a commit the old text was still in the file (free pages) and in the write-ahead log. After a scrub that changed rows, `VACUUM` and a truncating checkpoint run (`commit.compact_after_scrub`); a failure is recorded (`compaction_failed`) and retried at the next commit. Cost, measured on a copy of the 517 MB database of the midterm home: VACUUM 10.5 s, checkpoint 0.1 s, once after a hide; it needs about the size of the database in free disk space. `kb inventory` checks now include the raw bytes of the file and the log.
* **Converter upgrade:** a hidden source is no longer converted again (the original file stays, so an upgrade used to write its text back); the text-loss limit now counts the text of units that are no longer there unchanged (it counted only the net number of characters, so swapping a long unit for unrelated text of the same length passed). Re-measured on the 882 wiki pages (`docs/s4_upgrade_thresholds_sample30.json`; the first measure is kept as `..._net_loss_measure.json`): same output 100 percent of draws, curly quotes 82, **spaces tidied 0** (it squeezes the indentation of code blocks, so I no longer call it harmless), and 0 for each of the other four. The gate is therefore stricter than the one Roy approved on 2026-11-19; the limits (0.05 / 0.5 / 0.05, sample 30) are unchanged. **This is a change of behaviour for Roy to know about.**
* **Opened copies held open on Windows** (小o's open question): measured with a real open file; the copy stays, the inventory check names the class, the next commit removes it (regression test).
* **Accepted, not changed:** the scrub window can be opened by any code path that can write the database (it guards against carelessness inside kb, not against a program that can write the file, as the schema comment already says); the upgrade sample is fixed by its seed; the full application after the gate is one transaction per source, not one for all (running the upgrade again continues). **Not covered:** physical erasure of the files on the disk (level c) and the stale bytes of an expired proposal, which are not under the hide promise.

## Known limits
* The screening is a short pattern list (stated by the layer in every answer record).
* A claim's text is not compared with the answer; a quote proves only that the passage says it.
* Retrieval filters collections after ranking (four times as many hits are taken, then filtered), because `Searcher` has no scope parameter.
* Only Windows 11 was tested; process listing for the kill test and the netstat parsing are Windows paths.
* Real model behaviour is untested: the scripted model gives well-formed replies; a real model may often fail the agreed JSON form, which would make many answers `held`.
* Review fixes (round 1) have tests and mutants but no second look.
