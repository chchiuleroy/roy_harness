# S2 code review by 小o (rounds 1 and 2): findings and handling

Review contract v1.1, static (nothing was run by 小o). 8 `confirmed` findings (2 critical, 5 high, 1 medium) and 1 `needs_validation`. All eight confirmed findings were checked against the code before acting; all were real. The fixes were **not** sent back for a second review round.

| # | Finding | Severity (小o) | Handling |
|---|---|---|---|
| 1 | The tombstone trigger checked only that SOME approved delete proposal existed; it did not compare the proposal's target and level with the tombstone's, and level c rows were allowed. One approval could hide any target at any level | critical | `schema.py`: the trigger now requires the approved proposal's `diff.target_id` and `diff.level` to equal the tombstone's, accepts levels a and b only, and accepts kind `delete` only. Two more triggers freeze what was approved: a proposal's identity columns are never rewritten, and its difference is never edited (a decided one can only be blanked). Tests: reuse of an approval for another target, for a higher level, level c, and every edit of an approved or pending proposal. Mutants for each comparison and each trigger |
| 2 | A human or AI statement could borrow ANY approved proposal (even a delete proposal) to become committed | critical | The statement triggers and `commit.approval_sets` now require a fitting kind (ai to ai_edit; human to metadata or patch) and that the statement names its proposal in its own evidence. Six wrong combinations are tested at the database level and one at assembly level; a proposal whose state says approved but that has no approval row is tested too. Mutants for kind, binding and the approval row |
| 3 | A proposer could leave out `claims` and so escape the citation rule | high | `review._require_citations` (run at approval AND again at apply): an AI edit that writes `text`, `summary` or `note` must carry at least one citation, every claim must carry citations, every citation must exist. A retitle or a tag is a label, not a factual statement, and may go without. **Limit:** deciding what counts as factual by key name is a rule of thumb, not a classifier |
| 4 | Hiding a unit removed it from the index but `kb show` still printed its text and an AI proposer was still shown it | high | `commit.hidden_level`: `show` skips units hidden at level b (level a stays visible to the owner and says so); an AI proposer is refused for anything hidden at any level (it is never called); proposals about hidden subjects are refused. Tests for show at levels a and b, the proposer, metadata and patch proposals. Mutants for each |
| 5 | `resolve_patch` created, approved and applied the new correction in separate transactions and only then orphaned the old patch; a failure at the end left a half state | high | `_txn` now joins an outer transaction; `resolve_patch` runs all four steps in one. Test: a failure injected into the last write leaves every table exactly as before. Mutants for joining and for the wrapper |
| 6 | Patch replay moved a correction onto the ONLY identical unit anywhere in the document, with no check of context (unrelated boilerplate could receive it) | high | New outcome `relocated`: the only identical unit is followed automatically only if it shares the heading or a neighbour (before or after) with the old place; otherwise it goes to a person. Tests: the boilerplate case end to end, and each context rule in the pure function. Mutants |
| 7 | The upgrade distance used sets of units, so reordering or losing a duplicated paragraph looked like no difference | high | `upgrade.distance` takes the larger of the set measure and the ordered-sequence measure. Tests: reorder, dropped repeat, the exact values; an end-to-end refusal of a converter that reverses unit order. Mutants for each half |
| 8 | `approve` and `apply` read the proposal and the active commit before the write transaction began | medium | Every read that decides the outcome now happens after `BEGIN IMMEDIATE`; staleness is recorded inside the transaction and raised after it. Test: the reads happen with a transaction open. Mutants that move the read back out |
| 9 | (needs_validation) whether an external-model proposer could bypass the profile by calling `propose` without `external=True` | n/a | Not resolvable now (no model is connected). Recorded: when a real proposer is added, the integration test must show that the caller cannot choose `external=False` for an external provider, and that the refusal happens before the proposer is called |

## Round 2 (小o, static, on the fixes above)
Contract v1.1 again, nothing run by 小o. The main fixes held (transaction re-entry, stale marking, the tombstone and statement triggers, citation re-check at apply, the chunk memo, the distance function). **3 new `confirmed` findings, all high; each was checked against the code and was real.**

| # | Finding | Handling |
|---|---|---|
| R2-1 | `relocated` was bypassed: a shared heading alone counted as context, so boilerplate under the same heading received a correction automatically | A lone identical unit is followed only if its before- or after-neighbour fingerprint equals the old one and is not None (a document edge is not a neighbour); with several identical units both neighbours must match. Otherwise `relocated` goes to the queue. Tests: neighbour rules in the pure function and the boilerplate-under-same-heading case end to end. Mutants: heading alone, document edges as neighbours, after-neighbour ignored |
| R2-2 | Two read surfaces still showed hidden level-b content: `kb links` named a hidden source, and `review describe` printed ids, values and evidence for a proposal made before the subject was hidden | `links` uses the same `_general_access` check as `show`; `describe` prints a fixed note for any subject, target, unit version or citation hidden at level b. `commit.hidden_level` also understands unit ids. Tests: links for a level-b source; describe for AI, metadata, patch and delete proposals after hiding. Mutants for each surface |
| R2-3 | `statements.proposal_id` could be rewritten after commit, so the next commit no longer recognised the approval of the original statement | Trigger `statements_proposal_link_frozen`: once set (or once the statement is committed) the value cannot change. Test and mutant |

The run of the whole mutant set after these fixes left one survivor, which showed a test gap for a unit id as a delete target; fixed (see `S2_REPORT.md`).

Not sent back a third time: the round-2 fixes are small, but they add a trigger and change the approval screen and patch replay.

## What the triggers are and are not
They stop a bug, or a careless future code path, in kb from skipping the review rules. They do not stop someone who can write the database file directly (that person can also drop the triggers); that is outside what a local file can defend.
