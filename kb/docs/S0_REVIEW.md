# S0 code review by 小o (round 1): findings and handling

All ten confirmed findings were checked against the code before acting; all were real.

| # | Finding | Severity (小o) | Handling |
|---|---|---|---|
| 1 | The UPDATE trigger on the commit member tables checked only `NEW.commit_id`: a member of a published commit could be moved into a staging commit | high | `schema.py`: UPDATE now requires BOTH the commit a row leaves and the one it joins to be in staging. Test `test_members_cannot_be_moved_into_or_out_of_a_frozen_commit`; mutants `schema_commit_update_checks_new_only`, `schema_commit_members_never_frozen` |
| 2 | `chunk_id` sorted but did not de-duplicate its unit versions, contradicting the documented set semantics | medium | `ids.py`: sorted set. Test: `[V1]` and `[V1, V1]` give the same id; mutant `ids_chunk_not_deduplicated` |
| 3 | `_need_id` accepted any well-shaped id in any role | medium | `ids.py`: every id parameter has an allowed prefix set (source, unit, unit version, statement subject). Test with well-shaped ids of the wrong kind; mutant `ids_prefix_not_checked`. Tests now use role-correct ids |
| 4 | `sources` and `units` could be rewritten by UPDATE although they cannot be deleted | high | `schema.py`: both added to the no-update list, with a comment that re-homing a source would be a future migration with an explicit rule. Test `test_sources_and_units_are_identity_rows`; mutant `schema_sources_and_units_rewritable` |
| 5 | The attach journal was not validated (types, strict base64, digests of decoded bytes, path binding) | high | `attach.py`: `_validate_journal` checks every field, strict base64, both digests, the bound config path, the consistency of `existed_before` with the original bytes and that the entry is a valid kb entry; failures are typed `AttachRefused`. New `TestJournalIntegrity`; mutants for digest, path, type and consistency checks. Stated limit: the journal is trusted state; a local attacker who can write it and choose matching digests is out of scope |
| 6 | `--entry-only` / `--take-over` skipped the two-phase protocol and had no crash points | medium | `attach.py`: they now record `detaching` with the pre- and post-removal digests before replacing the file, and `recover()` understands them. Test `test_entry_only_detach_killed_at_each_point_then_recovered`; mutant `detach_entry_only_skips_journal_phase` |
| 7 | Only the temp files were fsynced; the directory entries made by rename were not | medium | New `durable.fsync_dir` (POSIX directory fsync; Windows best-effort FlushFileBuffers on a directory handle) called after every replace in `cas.py` and `attach.py` (including journal writes). Tests assert the calls happen. **Limit stated in the module and README: real power loss cannot be tested here, on either OS; Windows durability is best effort** |
| 8 | `audit.append` turned falsey non-mappings (`[]`, `""`) into an empty event | low | `audit.py`: only `None` means no ids; anything that is not a dict raises. Test and mutant `audit_falsey_ids_become_empty` |
| 9 | The R1 scanner is not a complete dependency proof; the test name claimed too much | medium | `importgraph.py` now resolves import aliases, reports `exec`/`eval`/`compile` and imports of computed names as findings; the test was renamed and the module docstring states what it can and cannot see. New tests and four mutants. The real harness still scans clean |
| 10 | The R2 probe observes only a subset of side effects | medium | Probe extended with started threads, changed environment variables, signal handlers and outbound connects; four new negative controls and mutants. The test module states that it does not measure CPU or memory and supports only "no observable side effect for the listed observations" |

Things 小o listed as not checked and that stay open: POSIX behaviour (flock, directory fsync), real power loss, a live MCP subprocess launch (S4), the harness full-suite comparison (`tools/removal_compare.py`, result in `docs/s0_removal_compare.json`).
Known and unchanged: no lock on the harness config between read and replace in `attach` (documented in the module docstring).
