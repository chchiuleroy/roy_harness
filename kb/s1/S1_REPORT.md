# S-1 報告 v2：基線、量測與凍結（2026-11-16；已併入小o 第一輪審查）

證據等級：**實測**＝這次跑出輸出（檔案在 `results/`）；**讀碼**；**推斷**；**猜測**。所有量測都是這台機器（Windows 11、16 執行緒、內顯 Vulkan）上的**單次或少量重複**，不是普遍值。

## 結論（有限 GO：允許進 S0 原型）
**GO，進 S0。** 說清楚它的範圍：這表示「嵌入後端與評估框架有足夠的初步可行性，允許開始建原型」，**不是**「完整設計 A 的成本、效益已被證明」，也不是「A 優於 A0」的裁決（那要等 S3 期中判定與 S9）。依據：
1. **常駐嵌入可行且便宜（實測）**：Qwen3-Embedding-0.6B（Q8 GGUF）經常駐 llama-server，單查詢中位數 41～51 ms、常駐記憶體約 0.78 GB，向量與現有索引一致（cos ≥ 0.9998）。
2. **現行流程有缺口（讀碼＋實測；原因未診斷）**：A0 只索引 `wiki/*.md`，不涵蓋 PDF 與其他模態（**定義與讀碼所得，不是檢索實測**）；而 A0 在自己擅長的 wiki 文字題上，成績比舊紀錄低（**實測**：real 25／27 對 26／27、blind1 33／40 對 36／40；差異原因沒診斷）。
3. **PDF 上存在待診斷的「頁面定位缺口」（實測；原因未知）**：稠密檢索找對檔案 28／30（補洞組），找對頁面只有 18／30（混合 19／30）。**這個缺口的成因沒有被隔離**：gold 品質、文字抽取、查詢生成方式、頁級聚合都是尚未排除的替代解釋。頁長診斷（描述性）：gold 頁 ≤ 4 個 chunk 時稠密 L2 為 11／17，更長的頁為 7／13；稠密 top-1 頁的 chunk 數中位數（4）等於全庫中位數（4），沒有明顯偏向長頁——但這不足以排除聚合偏差。

## 2. 嵌入後端（`embed_*.py`）
| 項目 | 結果（實測） |
|---|---|
| 常駐 llama-server（預設 4 slot、8192） | 就緒 2.4～6.5 秒；單查詢中位數 41～53 ms；p95 72～79 ms（有一次未帶指令前綴的早期試跑出現過 951 ms 單次離群）；**常駐約 9.4 GB**（不可接受） |
| 常駐 llama-server（`-np 1 -c 4096`） | 單查詢中位數 50～51 ms、p95 76 ms；常駐約 744～783 MB |
| 向量一致性 | 與現行 spawn 路徑 cos ≥ 0.9986（查詢）；與現行索引儲存向量 cos ≥ 0.9998（40 個 chunk；索引只存前 400 字，須用 `chunk_page` 重生全文——第一次比對漏了這點，已修） |
| Qwen3 在 CPU（sentence-transformers） | 載入 2.4 秒；單查詢中位數 251 ms、p95 1770 ms；cos vs 索引 ≥ 0.9976 |
| all-MiniLM-L6-v2（英文導向） | 單查詢 11 ms；blind1 15／40、blind2 14／40（對照 Qwen 33／40、32／40）。real 集未做同口徑比較。只說明英文導向小模型不能代替，**不代表 Qwen 最佳** |
| 批次吞吐 | 800 字 chunk 約 7.8～9 個／秒；PDF 全庫 31,980 chunk 嵌入 68 分鐘（一次性） |

**決定**：S1 用 Qwen3-Embedding-0.6B Q8 GGUF＋常駐 llama-server（`-np 1 -c 4096`）；CPU 路徑備援；4 slot 預設禁止。注意 4096 token 上限。

## 3. PDF 段落任務與基線（`tasks/pdf_tasks.json`）
- 來源：`_raw/` 222 份 PDF、8,072 頁、23.6 M 字元；抽樣 48 頁（種子 20261116，每份一頁），由小o 只看頁面節錄寫查詢（四類各 12）；gold 由抽樣程式決定。組別由 `sha256("kb-s1-v1|"+id)` 奇偶決定（`verify_groups.py` 可重算）：補洞 30、驗收 18。
- 頁級 BM25（全 48 題，只計正分頁面）：L1 26、L2@5 25；exact_term 12／12、paraphrase **0**／12、partial_memory 3／12。→ 題目可答且有鑑別力。
- **補洞組（n=30，修正零命中排序 bug 後重跑）**：BM25 L1 16、L2@5 15；稠密 L1 28、L2@5 18、L2@1 14；混合（RRF）L1 28、L2@5 **19**、L2@1 15。paraphrase 稠密 L1 10／10、L2 5／10；partial_memory L2 1／6。稠密解決了跨語言（中文查英文 PDF），沒解決頁面定位。
- **bug 紀錄**：第一版 `pdf_dense_eval.py` 在 BM25 零命中時把非正分頁面墊進榜單，再進 RRF；修正後 BM25 不變、混合 L2@5 由 18 變 19（舊輸出保存在 `results/pdf_dense_eval_gap_v1_padded_bm25.json`）。
- 揭露：驗收組的 BM25 彙總（L2 10／18）建題時被看過，只用來確認可答；驗收組因此標為**部分曝光**，該彙總不得被任何後續決定引用。

## 4. 影像頁面任務（探索性，不進驗收）
- 來源：《炁體源流》掃描頁 490 張（直排古籍）。用 Windows OCR 文字與「機器轉錄 markdown」做字對重疊把段落對到頁面（**實際篩選條件：重疊 ≥ 0.5、與第二名差距 ≥ 0.15**；最後抽中的 18 題剛好都有 ≥ 0.328 的差距），由小o 只看轉錄節錄寫 18 題。
- **限度**：①gold 由 OCR 文字比對決定，對「查 OCR 文字」的系統偏樂觀；②只有 1／18 肉眼確認；③那份 markdown 有明顯轉錄錯誤與重複（看原圖與節錄都看得到），是銀標不是金標；④有近重複段落（I15 與 I16 開頭相同，分屬 p129 與 p125），gold 可能不唯一。
- **處置**：18 題全部標 `exploratory_silver`、`acceptance_use=false`；S5 開工前以完全人工驗證的 gold 重建並凍結。補洞組 7 題基線（僅供參考）：BM25 4／7、稠密 3／7、混合 4／7；paraphrase 0／2。
